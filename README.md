# PYQ Repeated Question Analyzer

A self-study NLP project that compares **two years of exam papers per subject** and
surfaces questions that test the **same topic** — even when they are worded completely
differently (different story framing, different numbers, different phrasing).

- **Input**: 10 scanned PDFs = 5 subjects × 2 papers each
- **Pipeline**: PDF → OCR → boilerplate removal → question segmentation → preprocessing →
  TF-IDF + cosine similarity → thresholded matching → Streamlit app
- **Output**: an interactive app to explore related question pairs, plus a
  precision / recall / F1 evaluation against hand-labeled gold pairs

| Subject | Year A | Year B | Questions (A / B) |
|---|---|---|---|
| Data Structures | 2025 | 2026 | 16 / 12 |
| Digital Fundamentals (SEA II) | 2024 | 2025 | 12 / 11 |
| Discrete Mathematics | 2024 (ISA) | 2025 (SEA II) | 2 / 11 |
| Fundamentals of Programming Using C++ (SEA II) | 2024 | 2025 | 10 / 10 |
| Operating Systems | 2024 | 2026 | 16 / 11 |

## Features

- **Related-question pairs** — for a chosen subject, every pair of questions (one from
  each year) that the matcher links as same-topic, color-banded by similarity
  (high / medium / low) and expandable to read both questions in full, with the
  **common keywords** they share.
- **Live threshold slider** — drag it and watch the matches, and the evaluation
  metrics, update instantly (the precision/recall trade-off).
- **NLP evaluation tab** — precision, recall, F1, accuracy vs. hand-labeled gold pairs,
  per threshold and pooled across all subjects, with example false positives /
  false negatives.

## How the system works

1. **Extract** — each PDF page is read with PyMuPDF; scanned pages (< 20 chars) are
   OCR'd with Tesseract at 300 dpi. All 36 pages in this dataset are pure scans, so
   OCR does everything. Raw text is cached, so OCR never re-runs.
2. **Clean** — a ~13-pattern regex blocklist removes boilerplate (college banner,
   course codes, "Time: / Max Marks", bunch instructions, trailing outcome block).
3. **Segment** — a state machine splits the cleaned lines into questions using the
   papers' structure (`BUNCH I–V`, `OR` separators, `(COx: N Marks)` leaf tags),
   tolerating OCR noise. A one-time manual review is stored in
   `processed/segment_overrides/`.
4. **Preprocess** — lowercase, tokenize, remove stopwords, lemmatize → `clean_text`.
5. **Match** — per subject, TF-IDF (1–2 word grams) turns questions into vectors;
   cosine similarity gives an nA × nB matrix. Pairs scoring **≥ threshold** are
   shown as related. Default threshold 0.15: these are story-based questions, so
   true same-topic pairs score only ~0.10–0.45; higher thresholds find almost
   nothing, lower ones add noise. That trade-off is the app's slider.
6. **Evaluate** — the same matrix is scored against hand-labeled gold pairs to
   compute precision / recall / F1 / accuracy.

## Setup

Requirements: **Python 3.10+** and **Tesseract OCR v5** with English language data
(the code auto-detects `C:\Program Files\Tesseract-OCR\tesseract.exe`).

```bash
cd C:\Users\SINAN\nlp_q

# 1. Create the virtual environment and install dependencies
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt

# 2. Run the pipeline (each step caches its output, so it's safe to re-run)
.venv\Scripts\python src/extract.py   # OCR the PDFs -> processed/raw
.venv\Scripts\python src/clean.py     # boilerplate removal -> processed/clean
.venv\Scripts\python src/segment.py   # question segmentation -> processed/segmented
.venv\Scripts\python src/match.py     # TF-IDF matrices -> processed/matches
.venv\Scripts\python src/evaluate.py  # metrics -> processed/eval/results.md
```

> ⚠️ Use `.venv\Scripts\python` (not plain `python` or `streamlit`) — the packages
> and Tesseract live inside the project's virtual environment.

## Run the app

```bash
cd C:\Users\SINAN\nlp_q
.venv\Scripts\python -m streamlit run app.py
```

Open the URL Streamlit prints (usually http://localhost:8501). The app reads the
cached pipeline outputs — no re-OCR or re-matching happens.

- **🔗 Related Questions (Both Years)** — pick a subject from the sidebar; only
  questions with a related counterpart across the two years are listed. Expand a
  pair to read both questions and see the common keywords. Move the **Similarity
  threshold** slider to include more / fewer pairs.
- **📊 NLP Evaluation** — live precision / recall / F1 / accuracy for the selected
  subject, tables across thresholds, the pooled 5-subject view, and examples of
  what the matcher gets wrong.

## Results (summary)

At the default threshold 0.15, pooled across all 5 subjects:
**Precision 0.50 · Recall 0.39 · F1 0.44** (30 retrieved pairs, 15 true positives).

Raising the threshold to 0.35 gives precision 1.00 but recall collapses to 0.05 —
the classic lexical-matching behaviour on heavily reworded questions. Operating
Systems is the best case (stable jargon: "Banker's Algorithm", "Gantt chart");
C++/Discrete Mathematics the worst (same tasks, completely new vocabulary).

## Notes

- **Manual work lives in two places — don't delete them:**
  `processed/segment_overrides/` (segmentation corrections) and `labels/`
  (the gold pairs used for evaluation).
- Every pipeline step is rerunnable and cached; deleting `processed/` and
  re-running reproduces everything *except* the manual overrides.
- Full methodology, evidence, limitations and future scope: **`report/REPORT.md`**.
